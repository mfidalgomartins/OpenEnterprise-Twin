# OpenEnterprise Twin v0.6 — Identity, Tenancy and Durable Jobs

> Execute this plan test-first in small commits. Do not weaken the deterministic
> analytics kernel or make cloud infrastructure mandatory for local use.

## Goal

Ship a production-shaped identity and execution control plane that:

- authenticates end users with OIDC JWTs and service accounts with explicit API
  keys;
- authorizes every protected operation with server-side roles;
- isolates every mutable or persisted business resource by tenant;
- derives ledger actors and approvers from authenticated subjects;
- persists expensive work as lease-based, cancellable, retryable SQL jobs; and
- gives the browser a clear login, authorization and job lifecycle experience.

The architectural strategy remains a modular monolith. PostgreSQL is the durable
coordination layer, the API is the control plane, and a worker process executes
the existing pure analytical services behind application-owned ports.

## Non-negotiable contracts

### Principal

Authentication produces one immutable principal:

```python
Principal(
    subject="oidc-subject",
    tenant_id="northstar",
    roles=frozenset({"analyst"}),
    authentication_method="oidc",
)
```

- `subject` and `tenant_id` are normalized, bounded identifiers.
- roles are a non-empty subset of `viewer`, `analyst`, `approver`, `admin`.
- `admin` does not bypass tenant filters.
- the frontend can hide actions, but only the backend authorizes them.
- no actor, owner or approver identity supplied by a request body is trusted.

### Authentication modes

- `local`: development/test only, with one explicit local principal.
- `api_key`: service-account mode with configured subject, tenant and roles.
- `oidc`: production user mode with exact issuer and audience validation.
- production refuses `local`; production accepts `api_key` only when explicitly
  selected and configured with a strong key.
- OIDC accepts only configured asymmetric algorithms and a configured HTTPS JWKS
  URL. It validates signature, `iss`, `aud`, `exp`, `nbf`, key id and required
  subject/tenant/role claims. Algorithm confusion and unsigned tokens fail
  closed.

### Authorization matrix

| Capability | viewer | analyst | approver | admin |
|---|---:|---:|---:|---:|
| Read tenant resources and evidence | yes | yes | yes | yes |
| Create scenarios and submit analytical jobs | no | yes | no | yes |
| Create/revise/advance non-approval decisions | no | yes | no | yes |
| Approve evidence-bound decisions | no | no | yes | yes |
| Cancel own analytical jobs | no | yes | no | yes |
| Cancel any tenant job / inspect operational job detail | no | no | no | yes |

Approval still requires a subject different from the decision owner, including
for admins.

### Tenancy

- every repository constructor requires `tenant_id`; there is no optional or
  wildcard tenant path;
- all reads, writes, uniqueness checks, joins and pagination predicates include
  the tenant;
- tenant ownership is persisted on scenarios, experiments, datasets,
  calibrations, optimizations, decisions, decision events, monitoring reports
  and jobs;
- composite foreign keys prevent cross-tenant relationships;
- existing v0.5 data migrates to a documented `default` tenant;
- a resource in another tenant resolves as `404`, not `403`, to avoid existence
  disclosure.

### Job lifecycle

States are `queued`, `running`, `succeeded`, `failed` and `cancelled`.

Each job persists:

- tenant, kind, creator, request payload and request digest;
- idempotency key scoped by tenant and kind;
- attempt count, maximum attempts and next-attempt timestamp;
- progress percentage and a bounded safe stage name;
- worker owner, lease expiry, heartbeat and cancellation request;
- result resource type/id, result digest or stable RFC 9457 problem details;
- creation, start, completion and update timestamps.

Claiming uses a compare-and-swap/row-lock transaction. Workers heartbeat and
extend leases, stop at deterministic cancellation checkpoints, recover expired
leases after restart and retry only explicitly transient failures with bounded
backoff. Terminal updates verify current lease ownership.
